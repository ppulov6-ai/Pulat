# Pulat RAG — финальный проект модуля

Готовый консольный ассистент: ищет информацию в документах, передаёт найденный контекст языковой модели и показывает ответ с перечнем найденных источников. Реализованы постоянный векторный индекс, кэш ответов, выбор источника и обновление базы.

Подключена **Qwen2.5-3B-Instruct (Q4_K_M)** через локальный OpenAI-совместимый API `llama-cpp-python`. Программа сама запускает и завершает сервер модели. Векторные представления вычисляет **multilingual-e5-small**, поиск выполняет **ChromaDB**. Кэш хранится в **SQLite**. По умолчанию API-ключ и платная подписка не нужны; после установки и загрузки весов генерация и поиск работают локально.

## Запуск

Проверено на Linux x86_64, Python 3.12, CPU. Веса занимают около 2,6 ГБ; дополнительное место нужно окружению. Для локального режима желательно от 8 ГБ свободной оперативной памяти. Скорость зависит от процессора. Интернет нужен для установки пакетов и первой загрузки моделей.

```bash
git clone https://github.com/ppulov6-ai/Pulat.git
cd Pulat/Финальный_RAG_ассистент
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu
python download_models.py
python app.py
```

В Windows вместо `source venv/bin/activate` используется `venv\Scripts\activate`. Windows отдельно не проверялся. Если готового CPU wheel для платформы нет, `llama-cpp-python` потребует CMake и C/C++ компилятор.

Загрузчик использует официальные репозитории моделей, закреплённые ревизии и проверку SHA-256 каждого файла. Повторный запуск переиспользует проверенные веса и продолжает прерванные загрузки. Полные версии пакетов проверенного окружения сохранены в [requirements-lock.txt](requirements-lock.txt).

## Использование

Примеры вопросов:

- Что такое RAG?
- В каком году представили архитектуру трансформеров?
- Что такое векторная база данных?
- Кто создал Python и в каком году?
- Какой телефон службы поддержки проекта?

| Команда | Действие |
|---|---|
| `/help` | Список команд |
| `/stats` | Модель, количество документов, фрагментов, записей кэша и вызовов модели |
| `/sources` | Имена доступных документов |
| `/top_k 7` | Передавать модели до семи найденных фрагментов |
| `/source python.txt` | Поиск только в документе о Python |
| `/source all` | Поиск по всей базе |
| `/reindex` | Применить добавление, изменение или удаление документов |
| `/clear_cache` | Очистить сохранённые ответы |
| `/exit` | Завершить приложение и локальный сервер |

Положите свои `.txt` или `.md` в кодировке UTF-8 непосредственно в `data/`. Изменения применяются при запуске и по команде `/reindex`. База содержит материал урока 5.8 (`docs.txt`) и документ о Python из предыдущего ДЗ (`python.txt`).

Каждый вопрос обрабатывается отдельно: для уточнения включайте нужный контекст в сам вопрос. Под ответом показаны найденные фрагменты; это позволяет проверить, на чём основан ответ. Модель также получает инструкцию указывать номера источников, но небольшая модель не всегда соблюдает этот формат. Список поиска сам по себе не доказывает каждое утверждение ответа.

## Как устроен проект

1. `vector_store.py` читает документы и делит текст на фрагменты до 500 символов с перекрытием 80 символов. Короткие документы сохраняются.
2. `local_embeddings.py` вычисляет реальные E5-векторы с префиксами `query:` / `passage:`, masked mean pooling и L2-нормализацией.
3. ChromaDB выполняет семантический поиск с косинусной метрикой и необязательным фильтром `source`.
4. `rag_pipeline.py` передаёт найденный контекст в `provider.py`. Сервер Qwen доступен только на `127.0.0.1` и автоматически получает свободный порт.
5. `cache.py` сохраняет завершённый ответ вместе с источниками. Ключ учитывает вопрос, версию документов, модель, TOP_K, фильтр, промпт и параметры генерации. TTL — 24 часа. Ошибки и обрезанные ответы не кэшируются.
6. После изменения документов готовится новая коллекция; активный индекс переключается после её заполнения. При изменении версии базы старые ответы не выдаются по новому ключу.

Рабочие файлы создаются в `runtime/`: ChromaDB, SQLite-кэш, журнал вопросов и ответов `requests.jsonl`, журнал локального сервера. Их можно сохранить для собственного анализа; в Git они исключены.

## Настройки и OpenAI

Стандартный запуск работает без `.env`. При необходимости скопируйте `.env.example` в `.env` и измените `TOP_K`, `MODEL_THREADS`, `MAX_TOKENS` или `TEMPERATURE`.

Дополнительно поддержано прямое подключение к OpenAI:

```dotenv
BACKEND=openai
MODEL_NAME=gpt-4o-mini
OPENAI_API_KEY=ваш_ключ
OPENAI_BASE_URL=https://api.openai.com/v1
```

В этом режиме найденные фрагменты и вопрос отправляются в указанный API, оплачиваемый владельцем ключа. Ключ не включён в проект. **Проверки ниже выполнены с локальной Qwen; внешний OpenAI API не вызывался.**

Время измерено через `time.perf_counter()` от начала обработки вопроса до готового результата; первичная индексация выполняется до замера. Это время полного ответа, а не первого токена.

Подтверждено на реальных ответах:

- Трансформеры: **2017 год**, Python: **Гвидо ван Россум, 1991 год**.
- На вопрос о телефоне поддержки модель сообщила, что сведений нет. При фильтре `python.txt` модель также отказалась отвечать о RAG.
- Повтор из кэша сохранил текст ответа и все источники без нового обращения к модели.
- TOP_K=7 передал семь фрагментов вместо трёх и вызвал новую генерацию. Содержательно ответ почти не изменился: существенного прироста подробностей на этом вопросе нет.
- Короткий документ с кодом **СЕВЕР-42** попал в поиск; после замены текста ответ изменился на **ЮГ-73**, минуя старый кэш. Удалённый документ исключён из поиска. Изменения при перезапуске также обнаружены.

Полные вопросы, ответы, контексты и замеры: [прогон 1](evidence/pass_1.json), [прогон 2](evidence/pass_2.json). Вывод запуска: [verification.log](evidence/verification.log). Регрессионные проверки: [unit_tests.txt](evidence/unit_tests.txt). Реальная сессия консоли с командами и ответами: [console.txt](evidence/console.txt); завершение при EOF: [console_eof.txt](evidence/console_eof.txt).

Для воспроизведения:

```bash
python -m unittest -v test_regressions.py
python verify_project.py --passes 2
```

Первый набор проверяет поведение программы с изолированными тестовыми заменами. Второй действительно запускает Qwen и E5, выполняет поиск, генерирует ответы и записывает результаты. Тестовые документы создаются отдельно от основной базы.

Проверка 10, 50 и 200 запросов относится к повторным запросам к локальному кэшу с максимум 32 потоками, а не к одновременной генерации 200 ответов. Интерфейс проекта предназначен для одного пользователя. Отказы модели при отсутствии сведений проверены на конкретных вопросах; абсолютная защита от галлюцинаций не заявляется.

## Основа работы

Проект развивает `assistant_api` из архива урока `5-8-final.zip` и решения предыдущего ДЗ по кэшированию. Исправлены потеря коротких документов при разбиении, отсутствие обновления существующего индекса и неполный ключ кэша. Добавлены самостоятельное подключение локальной модели, источники, фильтр, команды управления и воспроизводимые проверки.

Официальные модели: [Qwen2.5-3B-Instruct-GGUF](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct-GGUF), [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small). Идентификаторы ревизий и хэши находятся в [model_manifest.json](model_manifest.json). Веса скачиваются отдельно и не включены в репозиторий.
