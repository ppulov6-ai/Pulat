# HTTP-доступ к проектам модуля 5

Для каждого проекта используется его собственное окружение Python, документы, параметры модели и кэш. Установите зависимости и скачайте проверенные веса по README выбранного проекта. В режиме local для 5.7 сначала запустите llama_cpp.server на 127.0.0.1:8765 по инструкции 5.7. Версия 5.8 запускает процесс модели самостоятельно. Перед запуском проверьте свободную память и диск; запускать обе модели одновременно для проверки отдельного проекта не требуется.

Команды из корня репозитория:

~~~bash
./Кэширование_RAG/venv/bin/python server/serve.py 5.7
# в окружении второго проекта
./Финальный_RAG_ассистент/venv/bin/python server/serve.py 5.8
~~~

Службы слушают адрес 127.0.0.1, порты 8757 и 8758 соответственно. На / доступна форма свободного вопроса. GET /health показывает готовность HTTP-процесса. Для проверки модели задайте новый вопрос:

~~~bash
curl --fail-with-body -H 'Content-Type: application/json' \
  --data '{"question":"Кто создал Python и когда вышла первая версия?"}' \
  http://127.0.0.1:8758/ask
~~~

Повторите запрос. У нового вопроса from_cache=false, у повторного true. Проверьте реальные ответы и записи SQLite: 5.7 пишет в results/logs.db, 5.8 в runtime/logs.db. CLI обоих проектов поддерживает /stats и /csv. Веб-записи имеют источник web. Ошибки обработки имеют суффикс .error. Тексты вопросов и ответов доступны владельцу базы. Веб-маршрута чтения чужих журналов нет.

Для доступа с рабочего компьютера можно пробросить нужный порт по действующему SSH-профилю. Публичное подключение домена и настройка обратного прокси выполняются отдельно. Два HTTP-процесса работают последовательно внутри каждого экземпляра; для текущих файлов кэша следует запускать один экземпляр на проект.
